# SIDOU 1.1: the small and medium items of 1.x (design, 2026-10-29)

Scope chosen by the user on 2026-10-29: every S and M item of the roadmap's 1.x and 1.0.x; the
large items (LAB's song bridge, instruments from a `.sid`, the browser editor, Live Link, the
felucca-bsp move) get their own design sessions later.

Numbers: image 544,912 bytes (1.0 ceiling 552,000 leaves 7,088; the app slot 581,564 leaves
36,652); RAMTEXT 48,736 of 49,152 (416 free); RAM ~15.7 KB free (FREE_RAM_MIN 8,976). Estimates
are mid-range, help-card text included.

## Decisions (the user, 2026-10-29)

Every recommendation below is accepted: macros as links stored with the sound (MACRO page);
MIDI export by the site pulling from the FM-1; flash: a 3-5 KB win-back, then 1.1's ceiling at
556,000 (558,000 if short); and items 1-14 as proposed.

## Items

1. **LAB press order.** STEP's mechanism (dbd21767): a lone SCL waits for EDIT. Done for SCL
   (608b5859). Also: EDIT pressed while ARP is held is vary (and spoils ARP's own release);
   EDIT pressed while LFO is held is undo (the page jump already made is harmless); the same in
   STEP for MUTATE and undo.
2. **fm1-emu bump.** Needs the network (cache stops at c1c045f). Rev in sidou-pack, emu-gate,
   sidou-tests, ergo; `cargo update -p fm1-soc -p fm1-core`. A modelled watchdog (~8 s) lets
   bootguard.rs use real resets and adds a hang-recovers test; usb.rs:1486 (fm1_reboot) and
   :1711 (watchdog feeds) adapt; budgets may move; rebuild the web demo. Merge before features.
3. **Filter LFO.** FILTER K4 `LFO` 0..32 in K1 detents each way (pitch-even), rate shared with
   PWM HZ and shown on the card (`LFO 1.2HZ`); the drawing shades the swept band.
   `LIVE_PARAM_FILTER_LFO` (59), a CC, a term in `cutoff_effective` via K1-walk position; the LFO
   phase must advance when either depth is set. Sound bytes 45 → 46 (with item 8: one format
   change; 1.0's 45-byte files load with defaults).
4. **ARP RATE.** MOD K4 RATE over LIVE's 9 `LIVE_ARP_RATES` (three clock-synced shown 1/32,
   1/16, 1/8); grey but settable with ARP off. `LIVE_PARAM_ARP_RATE` (60); CC 28 through the map
   row so learn can rebind it. Velocity target stays on NRPN and STATUS.
5. **DICE range and rhythm.** Frame at 2× while EDIT + SCL held: DENS, RANGE, SCALE, RHYTHM,
   ROOT. Range 1 OCT, 2 OCT (default, = 1.0), 3 OCT, BASS. Rhythm STRAIGHT (default, = 1.0 bit
   for bit), OFFBEAT, 3-3-2, FOUR, BROKEN; 8-place weight tables scaled by density; drums use
   rhythm, ignore range. `DICE` chunk v1 grows to 5 bytes (1.0 reads 3; a 1.0 rewrite resets the
   two to defaults: documented).
6. **ARP helper audition.** With TABLE's helper open the keys play the draft; each turn heard at
   once; header `HEARING DRAFT`; HOME discards, SAVE writes. An overlay {on, channel, first, len,
   left[10], right[10]} set via a `song_cmd` at a block's start; `tl()/tr()` in gt2_play.c read it
   only on the audition channel; the note's wave pointer redirected to the draft.
7. **Held step's locks.** Holding a STEP key sounds the step with its cutoff, resonance, filter
   mode, route and pulse locks; K1/K2 lock turns heard at once; chance doesn't apply. A
   `song_cmd` with up to five resolved locks, pinned in `lock_cur[ch]` while held. Same branch
   as 6 (RAMTEXT).
8. **Peek and macros.** Peek: note keys while EDIT is down play A for as long as EDIT is held;
   a tap with no key toggles A/B as now; any other control puts B back first. Macros: a sixth
   page MACRO (6/6): K1 RESO LINK (-8..+8, resonance follows cutoff; negative = squelch), K2 PWM
   LINK (-8..+8, PWM depth follows distance from 50 %); K3/K4 dark. Links belong to the sound,
   act wherever cutoff or width move (LIVE K1/K3, LAB, CC 74, mod wheel), are terms (reversible).
   Parameters 61, 62 (63 is the last free before midi_out's 64-bit PRESET_LOADS).
9. **Knob curves.** Walks (snap, then step) for PWM HZ (32 geometric 0.05-12.75 Hz), PWM depth
   (32, square law), VIB HZ (24 geometric), VIB DEPTH (32 geometric), VIB DELAY (24 quasi-log),
   the filter LFO, and the FX slots' Amount/A/B/Mix (a shape per algorithm and field). Stored
   values keep their meaning. Tests: monotonic, no dead detent, perceptual step within 0.5×-2× of
   the median, first detent moves the way you turned, CC reaches every position.
10. **Generative TRACKER (cut).** MUTATE and DICE in TRACKER (EDIT + ARP / EDIT + SCL, either
    order) on the shown voice's pattern; ROOT from a note key while EDIT + SCL held (TRACKER and
    STEP); a scale per lane (DICE bytes 5-6); chance shown as a marker; EDIT + ENV writes a filter
    sweep as GT2 `C` commands every 2 rows, never over a command. Generation code moves to
    app/song_gen.c. Deferred: generated arpeggio chords, multiplexed drums (instrument and
    wavetable writing: L).
11. **MIDI export.** The FM-1 shows no files over USB. The site's Songs-to-MIDI page gets "From
    the connected FM-1" (DIR, SysEx GET, convert in the browser); the walker learns wavetable
    arpeggios (checked against gt2-ref). TRKB: nothing writes it. Later: live notes out.
12. **BUSY retry.** Done on the Songs page (whole PUT resent after 1, 2, 4, then 5 s, ~60 s).
    Rule for sysex.md: a current-song PUT's BUSY (SAVE AS FIRST) is not retried.
13. **SysEx during a chord.** Today each DATA packet gets its own audio hold 100 ms apart (~10
    dips/s). Proposed: while a song plays or USB audio records, the upload waits for quiet (the
    ACK waits; the site shows "waiting for quiet"; toast `UPLOAD WAITS FOR QUIET`), and keys-only
    uploads use a longer gap (250 ms). Decided by ear on the device.
14. **REC compensated.** A fixed computed offset (~8-9 ms: the output's double buffer plus the
    key's read delay), both quantize modes, no setting. Emu test measures the digital part.
15. **USB PID.** `#define FELUCCA_USB_PID 0x51D0` in usb_config.h (usb.c already has
    `#ifndef`), tests usb_audio.rs:93 and usb.rs:76, VENDORED.md. Device: enumeration on three
    OSes, installers and the Hub still find the app; release notes say DAW routings may need
    reselecting.

## Flash

The recommended scope needs ~7.3-11.2 KB against 7,088 under 1.0's ceiling. Plan: 1.1's stage
556,000 (+4,000) after a 3-5 KB win-back; 558,000 if it falls short. Win-back: live.c's cold
half at -Oz (~1.5-2.5 KB), song_ext.c at -Oz (~0.5-0.8 KB), the font to glyphs 0x20..0xDC
(536 B). Not for 1.1: RED MOON RITE's art, the 8580 WEAK/STRONG profiles, the title cards.
RAMTEXT: 416 free, items 6 and 7 take ~180-270. hardware-test.md section 17 (code in Felucca's
debug area) would add 8 KB if the unit passes.
