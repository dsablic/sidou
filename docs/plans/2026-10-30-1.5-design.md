# SIDOU 1.5 (design, 2026-10-30)

The user, 2026-10-30: 1.1.x and what would have been 1.2 roll into one release, 1.5; the
quality pass (performance headroom, the ergonomics gate's speed, suggested automations) comes
after it. Facts below come from two read-only research passes over `main` after 1.1.

## Decisions (the user, 2026-10-30)

- **Flash:** a 2-4 KB win-back first, then 1.5's ceiling at 568,000 (+12,000 on 1.1's 556,000),
  leaving about 13.5 KB of the 581,564-byte slot for felucca-bsp and later.
- **Live Link** over USB-MIDI SysEx (Web MIDI; Felucca's USB descriptors untouched).
- **Browser editor:** SIDOU's C core compiled to wasm; librarian, export, instruments, tables, a
  basic pattern and orderlist grid, preview with SIDOU's own player.
- **Song bridge, `.sid` lift and TRACKER generation:** every recommendation below accepted.

No 1.5 item touches the audio interrupt (RAMTEXT has 80 bytes free after 1.1).

## 1. SIDOU's own USB ID

0x51D0 once pid.codes merges request #1341: `FELUCCA_USB_PID` in `platform/fm1/usb_config.h`,
the two tests (`sidou-pack/tests/usb_audio.rs`, `emu-gate/tests/usb.rs`), VENDORED.md; device:
enumeration on macOS, Windows and Linux, installers and the Firmware Hub still find the app.

## 2. LAB's song bridge

**Send (LAB → song):** writes the current sound into the song's **next free instrument** through
the edit queue, a cell at a time, while the song plays (the ARP helper's path, `arp_issue`,
generalised into a row and instrument batch writer); toast `SENT AS I0F LAB 03`. EDIT + send
writes over the instrument under INSTR's cursor, with a confirm.

| Sound field | Written as | Faithful |
|---|---|---|
| Waveform, ring, sync | wave row `ctrl\|gate`, `00`, `FF 00`; first wave | exact |
| ADSR | AD, SR; GoatTracker's hard restart (gate timer 2, HR on); attack 0 raised to 1 with a toast | exact (HR added) |
| Pulse width | pulse `$8H LL` | exact |
| PWM depth, rate, PWM LINK | a pulse loop (about 5 rows), the link baked | approximate (restarts per note, 50 Hz steps) |
| Cutoff, resonance, mode | filter rows; routing to **the current voice** | cutoff 11 → 8 bits |
| Filter LFO, RESO LINK | a filter loop, the link baked | approximate; takes over the song's filter (said on screen) |
| Vibrato | `vibdelay` and a calculated-mode speed row | approximate (50/n Hz, power-of-two depth) |
| ARP | a default chord written, TABLE's ARP helper opened on its rows | the helper decides |
| One-voice sync, fine tune, performance targets, FX slots | dropped; the screen says so | none |

**Exact round trip:** a trailer chunk keeps each sent instrument's 48-byte sound and a CRC of its
bytes and rows; a pull of an unedited instrument restores the sound exactly, an edited one is
decoded. **Pull (song → LAB):** from INSTR's cursor instrument; close to lossless for one-row
wave programs, the encoder's own loops and calculated vibrato; lossy for drums, absolute notes,
one-shot sweeps and gate-timer variants. **No GoatTracker audition before a send** (it would need
the audio interrupt); a send is non-destructive.

Gestures: send from LAB, pull from INSTR; the free combinations are checked against
[the button audit](2026-10-25-button-audit.md) in the plan. Cost about 3.5-5 KB flash, 100-150
bytes RAM.

**Gestures, as built (checked against [the button audit](2026-10-25-button-audit.md)):** in LAB,
**REC** sends and **EDIT + REC** replaces INSTR's instrument (a used one asks once, `REPLACE I05?
EDIT+REC`). REC outside the song views only armed record mode with a toast (the audit's "W"),
and EDIT + REC was free everywhere; REC's label reads as "record the sound into the song", and
an EDIT combination of the send gives the replace its variant. The other candidates: SEQ is
navigation, ARP alone in LAB is the first finger of EDIT + ARP (a release rule like SCL's), and
OCT- + OCT+ moves the octave first. On **INSTR**, **ENV**, **LFO** and **FX** pull the cursor's
instrument into LAB at their page: outside LIVE and LAB they did nothing, and from LIVE they
already open LAB at that page ("the labels lead"), so from INSTR they open it with the instrument.
A pull is one undo step in LAB. Hint line: `EDIT+KEY PEEK A  REC SEND`; the help cards of LAB and
INSTR list them.

## 3. Instruments from a `.sid`

The soloed voice's **next gate-on** is captured from the 6502's write sink (main loop): a
register image per play call for about 1 s or up to the voice's next gate-on; wave rows from
control and frequency (relative notes, delays for repeats), AD/SR (SR changes as `F6` rows),
pulse runs, filter rows only when the voice is routed. Digi bursts are refused (`DIGI: CAN'T
LIFT`); vibrato becomes a vibrato row or is dropped with a toast; 2SID picks the chip. The tune
owns the song's memory while it plays, so the result is a **GTI5 store file**, imported with a
prompt when the song comes back (the existing importer). Cost about 3-4.5 KB flash, about 550 B
of capture overlaying POOL while the tune plays, one store key.

## 4. Generated chords and multiplexed drums in TRACKER

- **Chords:** a few shared wavetable programs (major, minor, sus4, 7: rows `00 rel`, the
  waveform kept, so one program serves every instrument), written once through the batch writer;
  DICE on an ARP lane writes `note, instr, 8XX` cells. About 1-1.5 KB.
- **Multiplexed drums, time-shared first:** kick and snare on the strong beats, the lane's bass
  instrument between, pattern cells only; a new **BASS+DRUMS** lane role in the scene chunk (a
  format note). Combined drum-and-bass instruments later. About 0.5-1 KB.

## 5. Browser editor and librarian (site only)

SIDOU's `core/song`, `core/player`, `core/sid` and `core/fx` compiled to wasm: the same `.sng`
reader and writer as the device (trailer, CRCs, chunk rules, LOCK following edits), the same
player for preview. Scope:

1. **Library:** one page for the FM-1's store: list (type, size, CRC, free space), download, send
   with an overwrite check, delete (`Client.del()`), rename (get, put, delete), back up all and
   restore. Private files stay private.
2. **Export:** `.sng` with SIDOU's trailer by default; plain GoatTracker as a second button, with
   the channel-count warning; instruments as GTI5.
3. **Instruments and tables**, then **a basic pattern and orderlist grid** using only the
   device's own edit primitives (no instrument delete or reorder, no pattern renumbering in 1.5).
4. **Preview** with the wasm player (an instrument at a note, a pattern, the song).
5. An edited song goes to a **named file** (PUT target 0) by default; "load now" (target 2)
   explains SAVE AS FIRST.

No firmware change. 6-channel GoatTracker Stereo songs are read and kept.

## 6. Screen mirror: FM-1 Live Link

USB-MIDI SysEx (`7D`, a magic and a protocol version), **host-started** (START, a heartbeat every
2 s, auto-stop after 3 s), with `LINK` shown on the FM-1 while on.

1. **Mirror, cells mode:** a dirty bitmap of the 30x30 cells fed from what `ui.c` sends the LCD;
   a main-loop slice sends changed cells (font code, colour, large-text pieces, overlay masks) in
   short frames that give way to clock out, MIDI out and SysEx replies; region and painter cells
   as 4-bit pixels; a keyframe on request; a cap of about 20-24 KB/s (scopes about 10 fps, SCENE's
   art 1-2 fps). The viewer draws with `grid.c` and `font.c` in wasm, exactly as the LCD.
2. **Remote control:** buttons and encoders (Felucca's ids), released 500 ms after the last
   refresh; the keys stay MIDI notes.
3. **Scopes as state** (SID register snapshots from the main loop's shadow, the wasm SID core for
   large scopes) if room remains.
4. **For the other FM-1 firmwares:** `docs/reference/live-link.md` with frames, capabilities,
   session and input; test vectors and the shared viewer. A separately licensed module for them
   is the user's decision, after SIDOU ships it.

Cost about 2-3 KB flash, about 250-350 B RAM, a few % of a main-loop pass. Gates in emu-gate
(the USB host model) before any device check.

## 7. The move to felucca-bsp

Only if felucca-bsp #14 (SIE timing at `-O2`) and #15 (a raw MIDI-in hook) are settled: SIDOU
takes upstream code byte for byte. Both were open with no reply on 2026-10-30.

## Order

1. A flash win-back and the 568,000 stage.
2. The batch writer, then the song bridge (send, pull, the chunk).
3. TRACKER chords and drums (they use the batch writer); the `.sid` lift.
4. Live Link's firmware side and its emu gates; the spec.
5. The site: the wasm core, the library, export, the editor, the Live Link viewer.
6. The USB ID when pid.codes merges; felucca-bsp if unblocked.
7. One device session at the end.
