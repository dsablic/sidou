# M1d: MIDI as a first-class citizen (M1 scope), implementation plan

<!-- REUSE-IgnoreStart -->

> **For Claude:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development.

**Goal:** finish M1's MIDI scope from design doc section 16. M1a already
built the parser, the TRS/USB input path and a basic mapping. This plan
adds:
- a published CC/NRPN map covering every engine, character and effect
  parameter;
- MIDI learn;
- expression (velocity, pitch bend, mod wheel, aftertouch);
- knob moves sent out as CCs over USB;
- a measured note-on-to-sound latency test.

**Out of scope (M2):** clock and transport, multitimbral and whole-chip
modes, SysEx dumps and program-change banks.

**Context:**
- `app/midi_in.c` (parser), `app/midi_rx.c` (loss epochs), `app/live.c`
  (`live_cc`), `platform/fm1/midi.c` (rings, drain, USB/TRS);
- design doc section 16;
- M1c's effect slots and parameters, which land in `live` with M1c Task 2;
- `docs/reference/` for the published tables.

**Rules:** the same as M1a:
- SPDX headers on every file;
- the Co-Authored-By trailer;
- stage only your own files;
- judge every check by exit code;
- e2e over emulated TRS MIDI, because fm1-emu has no USB.

### Task 1: The CC/NRPN map as data
- `app/midi_map.{h,c}`: one table mapping each parameter id to a CC (7-bit)
  and/or an NRPN (14-bit), with range, curve and default. The parameter ids
  cover every live, SID, character and effect-slot parameter.
- Generate `docs/reference/midi.md` from the table with a host tool or
  test, and add a drift test so the docs can't disagree with the code.
- Use 11-bit cutoff and 12-bit pulse width at full resolution through NRPN
  (MSB/LSB, data entry, increment and decrement), with running NRPN state
  per channel.
- Replace the hard-wired `live_cc` mapping with the table, keeping the M1a
  numbers (74 cutoff, 71 resonance, 1 pulse width, 7 volume).
- **Tests:** each entry round-trips; NRPN parsing edge cases (null NRPN
  127/127, LSB-only updates, increment/decrement); the drift test.

### Task 2: Expression
- **Velocity:** sets a per-voice level. The SID has no per-voice VCA, so
  map it to a choice per preset: sustain level, filter cutoff offset, or
  pulse width. Default: off, i.e. full level.
- **Pitch bend:** range per instrument (default ±2 semitones), applied
  through the frequency registers. Test smoothness, including with the
  sync lead.
- **Mod wheel and channel/poly aftertouch:** assignable to a target
  (vibrato depth, pulse width, cutoff, a character macro).
- A small per-voice LFO for vibrato, driven by `live_tick`.
- **Tests:** register-level assertions, plus an e2e test that a pitch bend
  over TRS shifts the measured pitch.

### Task 3: MIDI learn
- **Gesture:** hold a button (documented in `docs/reference/controls.md`),
  turn a knob, then send a CC. The knob's parameter now follows that CC.
- Mappings persist in RAM. Saving to flash comes with M2's storage.
- They are cleared with a documented gesture.
- **Tests:** host tests for the learn state machine, and an e2e test of
  learning over TRS.

### Task 4: MIDI out
- Knob moves and parameter changes are sent as CCs/NRPNs over USB, so a DAW
  can record them as automation.
- Rate-limited and deduplicated. No output while the change came from
  incoming MIDI for the same parameter (no feedback loop).
- Uses the USB-MIDI IN endpoint, which M1a already enumerates.
- **Tests:** host tests of the outgoing stream (packetisation, rate
  limiting, feedback suppression). USB itself is a hardware check.

### Task 5: Latency
- **e2e test:** inject a note-on over the emulated TRS at a known cycle,
  then measure the cycles until the first non-silent sample appears in the
  audio DMA buffer. Assert at most one audio block (2.9 ms) plus the
  2 kHz UART poll. Report the distribution over many random phases.
- Use the timestamps M1a already records to place note-ons
  sample-accurately inside the block, if it fits the budget. Otherwise
  record why not in a decision record.

### Task 6: Docs
- The MIDI implementation chart in `docs/reference/midi.md`, generated.
- CHANGELOG, TESTING and controls docs.
