## 1. Storage

### 1.1 R: an unknown flash chip leaves SAVE waiting for ever

(Re-checked.) This is a blocker if v0.2.0 goes to units whose flash part isn't known.

- **Where:** `app/store.c:1663-1670` (`write_check`), `app/song_io.c:529-542`, `platform/fm1/store_fm1.c:148`.
- **What goes wrong:** when `flash_store_ok()` reads another JEDEC id, the store stays `STORE_STATE_UNMOUNTED`. `write_check` returns a final error only for FOREIGN, so here it answers `STORE_BUSY` for ever.
  - SONG SAVE stays in `SONG_IO_SAVE_WAIT` with `song->frozen = 1`. Every edit is then refused and every load says "SAVING" until a reboot.
  - Force also stays on, so `store_fm1_service` keeps the audio hold engaged.
  - Settings saves stay `asked`, and SysEx PUT NAKs BUSY.
- **Trigger:** an FM-1 batch with a different NOR part, then SONG SAVE.
- **Fix:** return a final error (`STORE_FOREIGN`, or a new `STORE_ERROR`) for UNMOUNTED, so each caller takes its "save failed" path.

### 1.2 R: one sector whose erase always fails stalls all maintenance

- **Where:** `app/store.c:1140-1143` (an erase error only counts `errors`), `1252-1260` (`ambiguous`), `1273-1275` (`recover_job`), `1291-1293` (`coldest(SEC_DIRTY)`).
- **What goes wrong:** the failed sector stays DIRTY, and usually AMBIG too.
  - `due()` picks it again every time: the lowest index for an ambiguous sector, otherwise the lowest erase count, and that count never rises.
  - No other sector is ever erased or collected, so the pool drains and small writes end up BUSY.
  - After a reboot, `rec` never clears, so every write is BUSY at once.
  - With a SAVE waiting, force keeps the audio held, so the device goes silent.
- **Trigger:** `fl_erase4k_ram` returns -3 or -4 every time on one worn sector.
- **Fix:** count failures per sector and retire it after N (keep it out of the pool, recovery and `reclaimable()`). At the least, rotate to other dirty sectors.
- **Test gap:** the host sim only injects random 3% failures (`sim.fail = 3`). It has no case of a sector that always fails.

### 1.3 R: SAVE says "SONG SAVED" without writing after SysEx changed the file

- **Where:** `app/song_io.c:520-528`.
- **What goes wrong:** the skip test checks dirty, the revision, live and the name. It never checks that the file in the store is still the one that was loaded.
- **Trigger:**
  1. Load "FOO" and make no edits.
  2. The host sends SysEx DEL "FOO", or PUT of a different "FOO". `midi_object_available` refuses only while song_io is busy.
  3. Press SAVE. It shows "SONG SAVED" and writes nothing, so the song is gone, or is the host's version, after power-off.
- **Fix:** record the file id at load and at save commit. Skip only if `store_file_open(target)` finds that same id.

### 1.4 m: settings and profiles report SAVED after a flash program error

- **Where:** `app/settings.c:180-183, 196-199`, `app/user_profile.c:155-160`.
- **What goes wrong:** both read "store idle after an accepted `store_put`" as committed. `writer_failed()` also leaves the writer idle, and `s->saved = crc` stops any retry.
- **Fix:** snapshot `store_stats.errors` when the write is accepted and compare once idle, as `sysex.c`'s DELETE path does. Or expose the last write's result.

### 1.5 m: one fast encoder twist formats a FOREIGN store, including a newer SIDOU format

- **Where:** `app/views.c:439`.
- **What goes wrong:** `steps > 1` arms and confirms the format in one event. FOREIGN includes `mount_newer`, so after a downgrade the user's songs are one gesture from erased.
- **Fix:** require a separate confirming event. Show "newer SIDOU format" apart from "foreign".

### Checked and correct

- **Write and erase:**
  - A record is written data → header → commit word.
  - The CRC covers header[0..11] and the data, never padding or uninitialised bytes.
  - The only reprograms only clear bits (the claim's same 32 bytes, the kill).
  - A sector is killed before it is erased. Torn erases, headers and claims are detected and marked AMBIG, then evacuated before the session writes.
  - `SEQ_GAP` lets the next session outrank a header cut mid-write.
- **Mount bounds:**
  - `rec_check` checks type, length and offset+size against 0xF00.
  - `file_ok` checks length ≤ 64K, the sector and chunk counts, sector < 73, no duplicated sectors, and each chunk against `free`.
  - Every mount slice makes progress. A foreign region is never written until a format; a newer format is never touched.
- **Collection and files:**
  - GC victims can't become the head or a file sector during the job, and copies get new sequence numbers.
  - Files claim their sectors up front. A cut leaves the old file or the new one.
  - `store_file_read` re-checks the file id on every call.
  - A SysEx PUT against a UI save gets BUSY on either side. Song load checks the whole-file CRC before parsing.
- **Settings and profile migrations:** bounded by the length and version checks.
- **gt2_stream, song_ext and SysEx DATA:** every `take()` fits its buffer, and the length arithmetic is overflow-guarded. SysEx DATA's offset and length checks hold.

## 2. Audio and interrupt context

### 2.1 B: with KEYS A over a playing song, the song can overwrite a key's note

(Re-checked.)

- **Where:** `app/keys_route.c:88-107`, `core/player/song_ctl.c:27-37` (`song_sink`), `platform/fm1/main.c:1564-1567`.
- **What goes wrong:**
  - `keys_route_sink` sends a newly held voice's registers to chip A at once, through the register ring.
  - `song_sink` keeps writing that voice until the interrupt applies TAKE.
  - TAKE is only queued in `song_pass()`, inside `play()`. For MIDI, the main loop runs `midi_drain()` → `commit_pass()` before `play()`, and `play()` can return early until the next tick (up to about 10 ms).
  - TAKE is also late when the command ring is full or it waits behind an edit's lock refresh (`song_ctl.c:207-213`).
- **Trigger:** KEYS A, a song playing on chip A, a MIDI note-on.
  1. The interrupt renders after `commit_pass`, so the key's frequency and gate-on are applied.
  2. In the same block the player loads its frame and writes the song channel's frequency and waveform+gate over them.
  3. TAKE lands later, and nothing rewrites the key's registers.
  - The note then holds at the song's pitch or waveform, or is cut off.
- **Fix:** a `volatile` mask of voices the keys hold, set by the main loop before the voice's first write. `song_sink` and `song_rewrite` drop writes for `taken | mask`. TAKE stays only for handing a voice back.

### 2.2 m: PLAY zeroes voices the keys hold in KEYS A

- **Where:** `core/player/song_ctl.c:79-83`.
- **What goes wrong:** the clearing loop writes 0 to all 25 registers, ignoring `taken`. A held key goes silent until it is let go, while live still has it gated.
- **Fix:** skip registers 0-20 of taken voices, as `song_rewrite` does.

### 2.3 m: a chip A swap mid-song drops the lock registers for up to one call

- **Where:** `core/player/song_ctl.c:397-404` (`song_ctl_chip_swapped`).
- **What goes wrong:** only `shadow[]` is replayed onto the new chip, not the locked filter and pulse values. Cutoff jumps for up to about 20 ms when a profile changes on a locked row.
- **Fix:** keep the last locked values and write them after `song_rewrite`.

### 2.4 m: `wait_for_drain` uses `idle` while a USB host is attached

- **Where:** `platform/fm1/audio.c:100`.
- **What goes wrong:** `wait_for_interrupt` (`main.c:1455`) spins instead of idling while `midi_usb_live()`, because of hardware-test 8's IN-packet loss under `idle`. This wait doesn't follow that rule.
- **Trigger:** a reset with no spare chip ready, or a full register ring, with a host attached.
- **Fix:** use the same rule here.

### 2.5 m: `scope_take_peaks` can lose a block's peak

- **Where:** `app/scope.c:105-110`.
- **What goes wrong:** the peaks are read and cleared with plain stores, so the interrupt's peak in between is erased. Cosmetic.
- **Fix:** do the read and clear under cli/sti.

### Checked and correct

- **Register ring:** volatile head and tail, correct fences, a power-of-two mask, the full test, one producer and one consumer.
- **Chip swap and chip B:** the swap protocol holds. `b_want` and `b_on` each have one writer. The fades are right.
- **Song command and event rings:** correct, including the in-place lock refresh. The hand-over's ordering is correct.
- **Frame clock:** at most one call per block, and no division in the interrupt.
- **The player in the interrupt:** only forward gotos and fixed loop bounds, so no song can make it loop.
- **Mixing:** MASTER's worst product is under 2^31, the chip mix saturates, and the fades stay within 128/128.
- **Hold and flash:** both DMA halves are zero before flash work runs. The interrupt does no flash reads (`-fno-jump-tables`; ram_audio.rs checks it).
- **Open hardware question (TODO.md already has it):** the SIE timeouts in Felucca's `usb.c:403-430` busy-wait inside TIMER5, which outranks the audio interrupt.

## 3. The player and the song model

### 3.1 B: notes 93-95 are written as REST, KEYOFF or KEYON

(Re-checked.)

- **Where:**
  - REC while playing: `app/song_view.c:288` (`pitch < GT2_NOTES`) and `:464` (`GT2_FIRSTNOTE + q[2]`).
  - STEP: `app/step_view.c:673` (clamps to 95) and `:612`.
- **What goes wrong:** GT2_LASTNOTE is 0xBC (pitch 92), so pitches 93, 94 and 95 become 0xBD, 0xBE and 0xBF. `row_valid` accepts them. TRACKER's own path refuses them (`tracker_view.c:571`, "NOTE OUT OF RANGE").
- **Trigger:**
  - REC playing at octave +3: keys 16-18, or MIDI notes 105-107.
  - STEP: turn PRESETS on a held step past G#7.
- **Fix:** clamp or refuse at `GT2_LASTNOTE - GT2_FIRSTNOTE` in `song_view_record_note`, `note_now` and `toggle_now`.

### 3.2 m: REC places a note in the wrong pattern during an orderlist repeat

- **Where:** `app/song_view.c:382-391` (`rec_place`).
- **What goes wrong:** past the last row it always moves to the next entry.
- **Trigger:** orderlist `D3 00 01`, NEAREST quantise, a key in the second half of pattern 00's last row on its first pass. The note goes to 01 row 0 instead of 00 row 0.
- **Fix:** follow the repeat, or take the next row from the player's ROW event.

### 3.3 m: REC writes the pitch heard, not the pitch the orderlist will play

- **Where:** `app/song_view.c:464`.
- **What goes wrong:** the entry's transpose isn't subtracted. With `F3 00`, a recorded C-4 plays back as D#4.
- **Fix:** subtract the transpose (refuse if it goes out of range), or document it.

### 3.4 m: a pattern boundary can need 10 lock slots, but there are 8

- **Where:** `core/player/song_ctl.h:168` (`SONG_ROW_LOCKS 8`), `song_ctl.c:1281-1299`.
- **What goes wrong:** at a pattern's last row, the look-ahead takes row 0 of this pattern and of the next. Each can carry 5 lock types.
- **Trigger:** row 0 of A and of B both carry all five types, orderlist `A B`. B's ROUTE and PULSE locks are lost.
- **Fix:** make it 10 (plus `edit_restore`'s room), or cap at 5 per source row.

### 3.5 m: changing an existing lock skips the pending-edit check

- **Where:** `core/song/song_ext.c:479-484`.
- **What goes wrong:** adding a lock checks for a pending edit, but changing one in place doesn't.
- **Trigger:** turn K1 on a locked row while an INS on that pattern hasn't been released. The value lands on the old row numbering, then shifts down a row.
- **Fix:** return `-GT2_ERR_PENDING` on the in-place path too.

### 3.6 m: lock values from a file aren't checked against `song_lock_max`, and their order isn't checked

- **Where:** `locks_of()` in `core/song/song_ext.c:380-392`, applied at `song_ctl.c:328-330`.
- **What goes wrong:** nothing bounds a filter-mode lock or checks that the records are sorted.
- **Trigger:** a `.sng` with a valid CRC and a filter-mode lock of 8. That sets $18 bit 7, so voice 3 goes off. Unsorted records make the binary search miss locks.
- **Fix:** validate the values and the order when reading, and drop a bad chunk.

### 3.7 m: one row's locks can be lost right after an edit applies

- **Where:** `core/player/song_ctl.c:1393-1397` (`poll_locks`).
- **What goes wrong:** `row_seen` advances before the `lock_edit_seq` check, so the skipped look-ahead is never retried.
- **Trigger:** a row boundary falls between `poll_applied` and `poll_locks` in one poll.
- **Fix:** don't advance `row_seen` while `lock_edit_seq` is set.

### Checked and correct

- **Bounds:** `tl`/`tr` bounds and jumps are safe, as are instrument 0 and anything above 63, unheld or out-of-range patterns, and a pattern shrunk while it plays.
- **No loops from song data:** the orderlist is read one byte per call, so no orderlist can loop the player. `reach()` and `next_pattern` are bounded.
- **The two readers agree:** notes, instruments, commands, 1..129-row patterns that need an end row, 0-row patterns, counts, and the stereo restart.
- **Edits and round trips:** the edit primitives refuse invalid states, and what they leave round-trips through save and load. Lock rebuild rules and undo/redo are correct.
- **GoatTracker 2 behaviour matches `player.s`:** hard restart order, firstwave $FE/$FF, funktempo, gate-off timing, and the repeat/transpose/restart quirk.

## 4. MIDI and SysEx

### 4.1 R: an input gap breaks SysEx on both ports and can leave a reply frame open

(Re-checked.)

- **Where:** `platform/fm1/midi.c:419-425` (`drain_pending`), `app/midi_rx.c:133-136` (`restart` → `parsers_init` sets `on_sysex = 0`), `app/sysex.c:203-207`.
- **What goes wrong:**
  - **(a)** `restart` clears both parsers' SysEx callback in the middle of the drain loop. `sidou_callbacks()` only restores it after the loop, so the rest of a frame after the gap in that pass is dropped. The host gets no ACK or NAK.
  - **(b)** `sysex_reset` runs whichever port lost bytes, so a TRS overflow aborts a USB transfer. `sysex_lost(port)` exists but has no caller.
  - **(c)** `sysex_reset` clears `tx_active` mid-frame, so channel packets follow a CIN 4 with no F7.
- **Trigger:** a DIR listing is streaming while a TRS flood of more than 256 entries (e.g. `B0 4A xx`) overflows the ring in one long pass.
- **Fix:** re-bind the callbacks inside `restart`. Keep separate loss tracking per port and call `sysex_lost(port)`. When a reset cuts a frame, send a closing CIN 5 `F7`.

### 4.2 m: CLOCK OUT's SPP can land inside a SysEx reply

- **Where:** `platform/fm1/midi.c:366-369`, `app/midi_sync.c:357-364`.
- **What goes wrong:** the SPP `F2 ll mm` is system common, so it ends the host's SysEx.
- **Trigger:** CLOCK OUT on, the song stopped mid-way, a GET or DIR running, then PLAY.
- **Fix:** hold SPP+FB back while `tx_active`.

### 4.3 m: FB with no position while the song is IDLE stays pending

- **Where:** `app/midi_sync.c:311-337`.
- **What goes wrong:** the request is never acted on, so it hijacks a later panel PLAY: it aligns the song when the panel's start should only follow the tempo.
- **Trigger:** a song loaded and never played, then `FB F8 F8 …`.
- **Fix:** in IDLE, treat RESUME without SEEK as START from 0.

### 4.4 m: `midi_clock_hold` has no caller

- **Where:** `app/midi_clock.h:37-41`, `midi_clock.c:68-77`.
- **What goes wrong:** F8s that arrive during a flash hold with interrupts masked (`store_fm1.c:70-123`) are stamped late, and the fit uses them.
- **Trigger:** a USB PUT while following a TRS clock. The phase drifts and the song can realign.
- **Fix:** report the hold's start and end from `operate()` through `midi_clock_hold`.

### 4.5 m: USB SysEx gets no back-pressure from SIDOU's ring

- **Where:** `platform/fm1/midi.c:157-161, 255-265`, `src/usb.c:851-858`.
- **What goes wrong:** EP1 NAKs only on usb.c's own ring, which never holds CIN 2-7 packets.
- **Trigger:** a 1 KB foreign SysEx dump during a long pass overflows the 256-entry ring. That gap releases every note and resets SysEx.
- **Fix:** gate EP1 on SIDOU's ring room. That needs a hook, which is an upstream candidate.

### 4.6 m: a dropped USB packet is counted twice

(Re-checked.)

- **Where:** `platform/fm1/midi.c:158-159`.
- **What goes wrong:** `midi_ring_push` already calls `lose()`, so `midi_stats.lost` doubles.
- **Fix:** remove the `midi_ring_lose` call.

### Checked and correct

- **Running status and real-time bytes:** running status survives real-time bytes and is cleared by F1-F7 and SysEx. Real-time bytes mid-message change no state. Stray data bytes and a lone F7 are harmless. F0 inside SysEx restarts it.
- **USB-MIDI packets:** the byte count is right for every CIN. Each source has its own parser.
- **SysEx frames and commands:**
  - The frame buffer has a single owner.
  - The decoded length is capped at 256 and the packed bytes at 293. The checksum matches the host crate.
  - The command lengths, DATA's alignment and bounds, and END's CRC are all checked.
  - The 2 s timeouts work.
- **Clock and program change:** the clock fit has no division by zero. Program change, NRPN and learn are all bounded.
- **MIDI out:** it never overfills its ring and never blocks.
- **The usb.c hooks:** correct, including the string descriptor lengths 38 and 22.

## 6. Tests re-aimed during M2
